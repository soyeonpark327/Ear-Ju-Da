# 모바일 앱 화면 개편

사용자가 제공한 10개 시안에 맞춰 기존 앱의 실제 화면을 교체한다. Figma의 `최종` 섹션은 크기·길이·폰트 속성 확인에만 사용했으며 원본은 변경하지 않았다.

## 화면과 동작

`mobile-entry.js`는 모든 일반 URL에서 공통 화면 컴포넌트(`mobile-views.js`)를 만들고 `mobile-app.js`가 기존 `js/api/`에 연결한다. 일반 화면과 예시 화면은 별도 HTML 구조를 사용하지 않는다. 기존 레거시 DOM에 CSS만 덧씌우던 어댑터는 제거했다.

- 메인: 실제 베테랑 조회, 더보기/접기, 방문 기록, 실제 노트 목록
- 프로필/달력: 실제 프로필·조언·예약 가능 날짜 조회
- 예약: 실제 슬롯/가격/잔액, 채팅 상담 선택, 포인트 사용 확인 후 기존 예약 API 호출
- AI 매칭: 고민/사진 전송, 실제 추천 카드와 프로필/예약 이동, 사진 오류 시 입력 유지
- 노트: 분야 필터, 실제 미리보기, 권한 있는 본문 조회, 확인 후 포인트 구매
- 채팅: 로그인/당사자/상담 시간 확인, 기존 메시지 조회/전송/Realtime/주기적 동기화, 완료 확인 및 보고서 이동
- 마이페이지: 실제 계정/포인트/예약/구매 내역/로그아웃. 계정 설정은 기존 기능을 보존한 account-settings.html로 이동

샘플 이름·점수·포인트·메시지를 일반 화면에 남기지 않는다. 초기 조회가 끝날 때까지 시안의 임시 데이터는 표시하지 않는다. 조회 실패는 오류/재시도 또는 빈 상태를 표시한다.

`?demo=1`은 같은 화면 컴포넌트를 쓰는 기존 디자인 확인 모드다. 결제·예약·메시지·AI 요청을 실행하지 않는다. 일반 앱 이용에는 이 매개변수가 필요하지 않다.

## 디자인

402px 프레임 유지. 메인 1682px, 날짜 선택 1122px, 노트 상세 1276px, 마이페이지 1153px 등 시안의 길이와 스크롤을 유지한다. 실제 데이터가 길거나 개수가 다를 때는 잘리거나 겹치지 않도록 필요한 높이를 사용한다. 작은 화면이라고 글자/배율을 임의 축소하지 않는다. Pretendard는 로컬 제공하며 OFL 라이선스를 보관한다. source text-specs.json은 원본에서 읽은 폰트 지표만 적용하며 화면 문구를 자동으로 교정하지 않는다.

통화 상담, 실제 환불 조건, 첨부 지원 범위 등은 기존 백엔드 구현을 따른다. 미지원 동작을 성공으로 표시하지 않는다. DB/API/보안 정책 변경 없음.

## 검증

- 일반 URL 8개에 모의 API를 연결해 새 공통 컴포넌트 렌더링, 예시 데이터 유출 없음, 가로 넘침/JS 오류 없음 확인
- 일반 URL에서 매칭→실제 ID 프로필 연결, 실제 슬롯/채팅 방식, 예약·구매 확인 취소, 실제 대화 표시와 입력 검사
- 실제 조회 API로 메인 목록/프로필 탐색 확인 (데이터 변경 없음)
- 예시 10개 화면 402px 크기/높이 캡처, HTMLHint 및 JS 문법/diff 검사
- 운영 데이터에 대한 예약 생성·포인트 차감·메시지 발송은 검증 과정에서 실행하지 않음
